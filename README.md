# 📚 Книжный год — Telegram-бот для учёта прочитанных книг

[@knizhny_god_bot](https://t.me/knizhny_god_bot) · Python · aiogram 3 · SQLite · Google Books API

Бот для тех, кто читает вместе: с партнёром, семьёй или компанией друзей. Записываешь прочитанную книгу в общий чат — бот считает, сколько прочитано за год, по людям и жанрам, и собирает список «что стоит прочитать».

> Это пет-проект и одновременно продуктовый кейс: от бытовой проблемы до продукта с внешними пользователями, встроенной обратной связью и метриками за два вечера.

---

## Проблема

Мы с женой решили устроить «книжный год» — читать и видеть прогресс друг друга. Нужно было место, куда складывать прочитанное и где в любой момент можно спросить «сколько с начала года».

Что рассматривали:

| Вариант | Почему нет |
|---|---|
| LiveLib / Goodreads | Отдельное приложение и соцсеть со своей лентой; нам нужен был счётчик, а не ещё одна платформа |
| Таблица | Неудобно вносить с телефона, никто не будет открывать |
| Группа в Telegram с хэштегами | Ноль разработки, но статистика — только «найти по хэштегу» |
| **Бот в общем чате** | Живёт там, где мы и так общаемся; записать книгу — одна команда |

## Решение

- `/add` — бот по очереди спрашивает автора и название, находит книгу в Google Books и предлагает правильное написание, затем жанр и реакцию 👍 / 😐 / 👎
- Карточка книги с кнопкой ✏️ — исправить или удалить свою запись
- `/stats` — прочитано за год: по людям и жанрам
- `/list` — мои книги, `/recommend` — что советуют другие
- `/top` — самые читаемые книги среди всех пользователей бота (анонимно)
- `/feedback` — предложить идею; `/news` — что нового
- Бот убирает за собой команды и служебные вопросы — в чате остаются только карточки книг

Работает в группах и в личке; у каждого чата своя статистика и свой набор жанров.

## Как развивался продукт

Каждая версия — ответ на конкретный сигнал от пользователей. Полная история — в [CHANGELOG.md](CHANGELOG.md).

**Релизный цикл:** один источник правды — `CHANGELOG.md` (SemVer, языком пользы для пользователя). Из него по тегу `vX.Y.Z` автоматически собирается GitHub Release, а бот после обновления сам рассылает этот же раздел в чаты и показывает его по `/news`.

| Версия | Что появилось | Откуда взялось |
|---|---|---|
| **1.0** | `/add`, `/stats`, `/list`, `/recommend`, `/undo` | MVP за вечер: минимальный цикл «записал → увидел счётчик» |
| | Жанр и флаг «стоит прочитать» | Первый запрос от первого пользователя — жены — ещё до запуска |
| **1.1** | Свои жанры кнопкой «➕ Новый жанр» | Фиксированного списка жанров не хватает: у каждой компании свои |
| | Мультичат, изолированная статистика и жанры, `/admin` | Решили открыть бота друзьям: «заодно посмотрим, кому такое нужно» |
| **1.2** | Нейтральная реакция 😐 | Бинарная оценка не подходила к «нормальным» книгам |
| | Проверка книг через Google Books, `/top` | Чтобы «Чехов — Вишнёвый сад» и «вишневый сад чехова» считались одной книгой и по ним можно было строить общую статистику |
| | Ввод автора и названия по шагам | Формат `Автор — Название` в одну строку оказался неудобным |
| | Чистый чат, ✏️ на карточке, личный `/list` | Чат засорялся командами; ошибки в записи нельзя было исправить |
| | `/feedback` → бэклог → уведомление автору идеи | Чтобы бэклог собирали сами пользователи |
| | `/news` и автоанонс релизов | Пользователи должны узнавать о новом без объяснений вручную |
| **1.2.1** | Автоматический переезд данных при превращении группы в супергруппу | Инцидент: после назначения бота админом Telegram сменил ID группы, и книги «пропали» из статистики |
| | Ключ Google Books API и повтор при ошибке | Инцидент: анонимная квота Google отвечала `429`, и проверка книг молча не срабатывала |

## Продуктовые решения

- **Telegram, а не приложение.** Пользователи уже там; нулевой порог входа — добавить бота в чат.
- **Пилот на домашнем компьютере.** Хостинг не нужен, пока не доказана ценность. Ограничение известно и принято: бот не работает, пока компьютер выключен (сообщения за последние сутки подхватываются после включения).
- **Диалог вместо формы.** Форма с двумя полями возможна только через Telegram Mini App и требует HTTPS-хостинга — несоразмерно для пилота.
- **Анонимная общая статистика.** В `/top` — только книги и цифры, без имён и названий чатов.
- **Склейка книг по фамилии автора и нормализованному названию** (без регистра, ё/е, пунктуации, инициалов и отчеств). Известное ограничение: «Чехов Антон» (фамилия первой) посчитается отдельно; варианты из Google Books в правильном формате это почти исключают.
- **Открыт для всех, без белого списка.** Осознанно: цель пилота — увидеть, кому это нужно.

## Метрики

Через `/admin` (доступна только владельцу):

- подключённые чаты и сколько из них активны / удалили бота
- чаты с книгами, число читателей, книг всего и за год
- по каждому чату: дата подключения, последняя книга, последняя активность

## Архитектура

```
Telegram ⇄ aiogram 3 (long polling) ⇄ bot.py ⇄ SQLite (books.db)
                                         └──→ Google Books API (поиск и нормализация книг)
```

- Один процесс, long polling — не нужен публичный адрес и HTTPS
- SQLite с версионируемыми миграциями (`PRAGMA user_version`), только параметризованные запросы
- Таблицы: `books`, `genres` (свои у каждого чата), `chats` (активность и анонсы релизов), `feedback`
- Состояние диалогов — в памяти процесса; при перезапуске незавершённый диалог просто начинается заново
- Автозапуск — Планировщик заданий Windows → WSL (`run.sh`), перезапуск — `restart.sh`

## Запуск

```bash
git clone https://github.com/Perevezentsev/bookbot && cd bookbot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN от @BotFather, при желании ADMIN_ID и GOOGLE_BOOKS_KEY
.venv/bin/python bot.py
```
