# CLAUDE.md — «Книжный год» (bookbot)

Telegram-бот [@knizhny_god_bot](https://t.me/knizhny_god_bot) для учёта прочитанных книг в общих чатах. Публичный репозиторий github.com/Perevezentsev/bookbot — это ещё и продуктовый кейс для портфолио (см. README.md), так что качество текстов, коммитов и changelog важно.

## Где и как работает бот

- Боевой экземпляр запущен **из этой же папки** (`~/bookbot` в WSL Ubuntu на домашнем ПК Windows): Планировщик заданий Windows (задача `BookBot`, при входе) → `run.sh` → `.venv/bin/python bot.py`, лог — `bot.log`.
- `run.sh` — **сторож**: держит ровно один экземпляр (`flock` на `.run.lock`, там же pid сторожа; второй `run.sh` сразу выходит) и перезапускает бота, если процесс завершился. Пауза 10 с, при падениях сразу после старта растёт до 5 мин; в лог — одна строка `run.sh: …` на перезапуск.
- **Никогда не запускай `python bot.py` здесь вручную**: два экземпляра с одним токеном → `TelegramConflictError`. Проверяй код без запуска бота (см. «Проверка»).
- Применить изменения: `./restart.sh`. Если сторож жив — ставит флаг `.restart` и гасит только его дочерний процесс, сторож сразу поднимает бота заново; если сторожа нет — запускает задачу Планировщика. В конце показывает процессы: должен быть один `run.sh` и один `python bot.py`. После — `tail bot.log`.
- Полная остановка: `./stop.sh` (сторож, бот, задача Планировщика). `pkill python` бота **не** останавливает — сторож его перезапустит. Запустить снова — `./restart.sh`.
- Старт переживает отсутствие сети: `until_online()` повторяет `bot.me()` и `set_my_commands` с паузой 5 с … 5 мин; дальше обрывы сети переживает сам polling aiogram.
- Бот раз в минуту обновляет `.alive`. После старта, если `.alive` (или, без неё, последняя строка `bot.log`) старше 5 минут (`DOWNTIME_MIN`), пишет `ADMIN_ID` в личку «Бот снова работает, был недоступен с … до …». Обычный `./restart.sh` сообщения не вызывает.
- `wsl --shutdown` и выключение ПК останавливают бота; после входа в Windows он поднимается сам и подхватывает апдейты за последние сутки. Сон ПК процесс не перезапускает — бот просто «замирает» и продолжает (сообщения о простое не будет).
- Лимит Планировщика «72 часа» бота не убивает: Windows гасит свою оболочку задачи, а процессы в WSL продолжают работать (проверено по логу).
- Python 3.12, зависимости — `requirements.txt` (aiogram 3, python-dotenv; aiohttp идёт с aiogram).

## Секреты и данные — не трогать и не коммитить

- `.env`: `BOT_TOKEN`, `ADMIN_ID`, `GOOGLE_BOOKS_KEY`, `ALLOWED_CHAT_IDS`, `GENRES`. Не выводи значения в ответах и логах. Шаблон — `.env.example` (его обновляй при новых переменных).
- `books.db` — живая база пользователей. `books.db*` (бэкапы), `bot.log`, `.venv/`, служебные `.run.lock`, `.alive`, `.restart` — в `.gitignore`.
- **Перед миграцией схемы или массовой правкой данных** — `cp books.db books.db.bak-$(date +%Y%m%d-%H%M)`.
- Для экспериментов с данными работай на копии: `cp books.db /tmp/test.db` и `DB_PATH=/tmp/test.db`.

## Архитектура (один файл `bot.py`)

Порядок секций в файле: конфиг из `.env` → релизы (разбор `CHANGELOG.md`) → база и миграции → нормализация книг и поиск в Google Books → клавиатуры → общие помощники → обработчики → `main()`.

**Таблицы SQLite:** `books` (chat_id, user_id, user_name, author — каноничное имя, author_id, title, genre, rating, book_key, verified, created_at), `authors` (name «Имя Фамилия», wikidata — Q-номер или NULL, born, died), `author_aliases` (варианты написания: key=norm, kind typed|name, sure), `chains` (сообщения незаконченной записи книги), `genres` (свои у каждого чата, UNIQUE(chat_id, key)), `chats` (активность, `removed`, `notified_version`), `feedback` (бэклог от пользователей).

**Ключевые механики:**
- **Миграции** — в `init_db()`, идемпотентные; версия схемы в `PRAGMA user_version`. Новая миграция = новый блок `if user_version < N`.
- **Изоляция чатов** — все запросы к данным фильтруют по `chat_id`. Исключения: `/top` (анонимная статистика по всем чатам — только книги и цифры) и админ-команды.
- **Нормализация книг** — `norm()`; `key_for()` = `#ID_автора|название` (без сопоставленного автора — старый `book_key()` = `фамилия|название`). По `book_key` склеиваются одинаковые книги в `/top`. `verified=1` — запись выбрана из вариантов.
- **Авторы** — `author_fits()`: фамилия среди слов написанного с допуском опечаток, первый инициал совместим с именем. Шаг «Это какой автор?» (`got_author()`): авторы из базы (`similar_authors()`), затем Wikidata (`search_authors()` — полнотекстовый поиск с фильтром человек+писатель; `None` = недоступна, тогда только база). Без вопроса — только `sure_alias()`: однозначное написание (имя/инициал или единственный кандидат в Wikidata), ведущее к одному автору; при правке через ✏️ спрашиваем всегда. `migrate_authors()` при старте сопоставляет записи без author_id (без сети — откладывает).
- **Карточка книги** — одно сообщение, которое `advance()` ведёт по шагам: автор → проверка автора → название → проверка книги → жанр → реакция → итог с кнопкой ✏️. Правка через ✏️ возвращает карточку на нужный шаг.
- **Цепочка** — `chain_start/chain_note/chain_finish/chain_abort` (таблица `chains`): команда /add, вопросы и ответы живут, пока идёт запись; карточка готова — удаляются. `sweep_chains()` раз в минуту убирает брошенные на `CHAIN_TTL_MIN` минут вместе с недооформленной записью; новый /add убирает прежнюю сразу.
- **Диалоги** — `ask()` + словарь `pending[(chat_id, user_id)]` (в памяти; после рестарта незавершённый диалог теряется — это допустимо). Ответы ловятся реплаем на сообщение бота; ForceReply адресуется через `mention()`.
- **Чистый чат** — одиночные команды `drop()` удаляет сразу (в группе нужен админ с правом удаления; без него молча не удаляет).
- **Владелец записи** — кнопки карточки работает только у автора (`owned_book()`).
- **Супергруппы** — при смене ID группы `migrate_chat()` переносит книги, жанры и пожелания.
- **Google Books** — `search_books()`: ключ из `.env`, один повтор при 429; при ошибке возвращает `None` (в лог — текст ошибки Google) и бот продолжает без проверки. `find_candidates()` берёт из Google только похожие названия подходящего автора; `[]` (ничего похожего) → карточка «не нашёл» с кнопками исправить/оставить.
- **Ответы** — `parse_mode=HTML`: весь пользовательский текст через `html.escape`.
- **Похожие книги** — `match_score()`: нечёткое сравнение (опечатки по числу правок, порог зависит от длины; автор — любое слово к любому). При записи `find_candidates()` ставит похожие книги из бота (📚) перед вариантами Google; `after_verify()` переспрашивает, если человек уже записал эту книгу в этом чате в этом году.
- **Админ** (`ADMIN_ID`): `/admin`, `/backlog`, `/done N`, `/reverify`, `/dups` (слияние похожих авторов и книг с бэкапом базы), `/myid`, `/chatid`.

## Релизы — единственный источник `CHANGELOG.md`

- Формат: Keep a Changelog по-русски, SemVer, **языком пользы для пользователя, не списком коммитов**. Под заголовком версии — одна строка-итог. Разделы: «Добавлено», «Изменено», «Исправлено», при необходимости «Приватность», «Дальше». Заголовок строго `## [X.Y.Z] — ГГГГ-ММ-ДД`.
- Бот читает `CHANGELOG.md` при старте: `/news` и **автоанонс** нового раздела во все активные чаты один раз после рестарта.
- Порядок выпуска: изменения → раздел в `CHANGELOG.md` → `./restart.sh` (анонс ушёл) → коммит → `git tag -a vX.Y.Z -m "vX.Y.Z — заголовок"` → push ветки → push тега → GitHub Actions (`.github/workflows/release.yml`) создаёт Release из раздела changelog.
- Любое изменение, заметное пользователям, — с новой версией. Внутренние правки (рефакторинг, админка) — без анонса; можно копить и выпускать вместе со следующей пользовательской версией.
- Админские команды в changelog не упоминаем.

## Проверка

Автотестов пока нет. Проверяй без запуска бота:
- `python -m py_compile bot.py`
- сценарии — импортом модуля с фейковым токеном и временной базой, с заглушками `Message`/`CallbackQuery`/`Bot` и подменой `search_books`:
  `BOT_TOKEN=1:test DB_PATH=/tmp/t.db .venv/bin/python -c "import bot; ..."`
- миграции — на копии боевой базы.
Живую проверку в Telegram делает Алексей после `./restart.sh`.
